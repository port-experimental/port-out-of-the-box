# terraform-port-workflow-root-module

Composes the `terraform-port-workflow` child module to deploy an incident
auto-triage workflow. Members select an incident, Port AI investigates it using the
Port context lake, and the workflow writes the triage results back to the incident
entity.

## Architecture

```text
Pipeline environment variables
  └── Port provider
        └── terraform-port-workflow child module
              └── Incident auto-triage workflow
                    ├── Member selects an incident
                    ├── Port AI performs triage
                    └── Incident entity is updated
```

The root owns provider configuration and the incident triage workflow definition. The
child module owns the `port_workflow` resource.

## Prerequisites

- Terraform >= 1.16
- `port-labs/port-labs` provider >= 2.25.3
- An `incident` blueprint with `status`, `severity`, `root_cause`, and `analysis`
  properties
- `PORT_CLIENT_ID` and `PORT_CLIENT_SECRET` available as protected pipeline
  environment variables

## Configuration

The workflow definition is supplied from `local.incident_auto_triage`:

```hcl
module "incident_auto_triage_workflow" {
  source = "github.com/port-experimental/terraform-port-workflow?ref=1.0.1"

  identifier                = "tf-incident-auto-triage"
  title                     = "Incident Auto-Triage Generated by Terraform"
  category                  = var.category
  allow_anyone_to_view_runs = true
  nodes                     = local.incident_auto_triage.nodes
  connections               = local.incident_auto_triage.connections
}
```

The workflow is self-service for Members. Its AI step can inspect Port blueprints and
entities, including the selected incident and its related service. The final
`update-incident` step sets the incident status to `investigating` and writes the AI
summary, severity, root cause, and recommended action to the incident entity.

## Optional notifications

To notify another system after the incident update, append a node to
`local.incident_auto_triage.nodes` and add a connection from `update-incident` to that
node. Store API tokens as Port workflow secrets and reference them with
`{{ .secrets["SECRET_NAME"] }}`.

### Slack

```hcl
{
  identifier = "notify-slack"
  title      = "Notify Slack"
  webhook = {
    url    = "https://slack.com/api/chat.postMessage"
    method = "POST"
    headers = {
      Authorization = "Bearer {{ .secrets[\"SLACK_BOT_TOKEN\"] }}"
    }
    body = {
      channel = "#incidents"
      text    = "Incident {{ .outputs.trigger.incident }} is {{ .outputs[\"ai-triage\"].response | fromjson | .severity }}."
    }
  }
}
```

### Microsoft Teams

```hcl
{
  identifier = "notify-teams"
  title      = "Notify Teams"
  webhook = {
    url    = "{{ .secrets[\"TEAMS_WEBHOOK_URL\"] }}"
    method = "POST"
    body = {
      type = "message"
      text = "Incident {{ .outputs.trigger.incident }} triage is complete."
    }
  }
}
```

### Jira

```hcl
{
  identifier = "create-jira-issue"
  title      = "Create Jira Issue"
  webhook = {
    url    = "https://your-domain.atlassian.net/rest/api/3/issue"
    method = "POST"
    headers = {
      Authorization = "Basic {{ .secrets[\"JIRA_BASIC_AUTH\"] }}"
    }
    body = {
      fields = {
        project   = { key = "INC" }
        issuetype = { name = "Task" }
        summary   = "Triage: {{ .outputs.trigger.incident }}"
      }
    }
  }
}
```

Then add the notification after the entity update:

```hcl
{
  source_identifier = "update-incident"
  target_identifier = "notify-slack" # or notify-teams / create-jira-issue
}
```

## Inputs

- `category` — Port category for the workflow. Defaults to `Terraform`.
- `port_client_id` — Port client ID. Sensitive; defaults to `null`. Prefer supplying
  this through pipeline environment variables.
- `port_client_secret` — Port client secret. Sensitive; defaults to `null`. Prefer
  supplying this through pipeline environment variables.

## Outputs

- `workflow_id` — Port's internal identifier for the workflow resource.
- `workflow_identifier` — Configured workflow identifier.
- `workflow_title` — Workflow title displayed in Port.
